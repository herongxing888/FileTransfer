# File Transfer — 局域网两机互传桌面应用设计

**日期**：2026-05-27
**状态**：已与用户确认，待进入实施计划阶段

## 目标与范围

做一款 Windows 桌面应用，让两台 Windows 电脑在**同一局域网**下能快速互传图片、文件、文字。

**v1 明确包含**：

- 局域网自动发现 + 一次性配对
- 两机一对一互传：文本、文件、图片（剪贴板粘贴的图片走文件流程）
- 聊天式 UI：文字直接输入、文件拖拽 / 点 + 选
- TLS 加密 + 配对码防 MITM
- 仅当前会话可见，关闭即清空（不持久化历史）

**v1 明确不包含**（YAGNI）：

- 跨网络（公网 / 不同 Wi-Fi）传输 → 留待 v2
- 多设备（>2 台）配对 → 用户确认只 2 台
- 断点续传
- 历史记录持久化
- 资源管理器右键菜单集成
- 后台剪贴板自动同步
- 移动端 / Mac / Linux 客户端

## 使用者画像

用户自己拥有的两台 Windows 电脑（如家里主机 + 笔记本），两机都装本应用，首次互相配对一次后长期使用。

## 技术选型

- 平台：Windows 10 / 11
- 框架：.NET 8 + **WPF** + MVVM
- 测试：xUnit
- 加密：.NET 内置 `System.Security.Cryptography`（`CertificateRequest.CreateSelfSigned` 原生支持自签证书，无需第三方库）

**为什么 WPF 而不是 WinUI 3**：WPF 文档生态成熟、AI 辅助效果好、第三方控件库完整。WinUI 3 也行但调试与发布工具链不如 WPF 稳。本项目无需用到 WinUI 3 独有的现代控件。

**为什么不用 mDNS/HTTPS 等标准协议（方案 B）**：用户确认只 2 台 Windows，跨网/手机端走 v2 重写传输层，方案 B 的可扩展性优势在本项目用不上。

## 组件架构

```
+-----------------------------------------------------+
|  FileTransfer.App  (WPF 入口)                       |
|  - App.xaml / MainWindow.xaml                       |
|  - ViewModels (MVVM)                                |
+-----------------------+-----------------------------+
                        |
+-----------------------v-----------------------------+
|  FileTransfer.Core  (与 UI 无关的核心逻辑库)        |
|                                                     |
|  Discovery (UDP 广播)                               |
|  Pairing   (TLS 指纹确认 + 4 位配对码)              |
|  Transport (TCP + TLS + 帧编解码)                   |
|  Protocol  (HELLO / TEXT / FILE_* / PING)           |
|  SessionState (内存)                                |
+-----------------------------------------------------+
```

**项目分层**：

- `FileTransfer.Core/` — 纯 .NET 类库，不引用 WPF。所有网络、加密、协议、状态都在这里，可脱离 UI 单测。
- `FileTransfer.App/` — WPF 项目，只做 UI 绑定。
- `FileTransfer.Core.Tests/` — xUnit 测试。

每个模块对外只暴露窄接口（如 `IDiscovery`、`ITransport`），可独立替换与测试。

## 配置存储

- 路径：`%APPDATA%\FileTransfer\config.json`
- 内容：
  - 本机自签 X.509 证书（公钥）+ 私钥（用 Windows DPAPI 加密后存）
  - 本机设备名（默认 = `Environment.MachineName`，用户可改）
  - 已配对对端的公钥指纹（SHA256，hex）
  - 已配对对端的设备名（仅显示用）
  - 接收文件保存目录（默认 `%USERPROFILE%\Downloads\FileTransfer\`）
  - 是否开机自启

## 启动流程与配对

### 首次运行（未配对）

```
[A 机]                                  [B 机]
   |-- 启动时生成自签 X.509 证书 ----------|
   |   私钥存 Windows DPAPI 加密            |
   |                                       |
   |== UDP 广播 "Hello, fp=..." 每 5s ====|
   |   监听端口 47100                      |
   |                                       |
   |   <UI: "搜索附近设备" 列表显示 B>     |
   |   <用户点 "配对">                     |
   |                                       |
   |--- TLS 握手到 B:47101 ---------------->|
   |                                       |
   |  <两边 UI 都弹出 "配对码 XXXX">       |
   |   = fingerprint 派生的 4 位数字        |
   |                                       |
   |   <用户在两边都点 "确认"> ------------|
   |                                       |
   |--- 双方持久化对端指纹 ----------------|
   |                                       |
   |   状态: 已配对                        |
```

**配对码算法**：把两边公钥指纹按字典序拼接后 SHA256，取前 14 bit 转 4 位十进制（0000-9999，碰撞概率约 1/16384）。两边同时计算，结果一致。MITM 不知道两边真实公钥，算出来对不上，用户会发现。

### 已配对后启动

```
启动 → 加载本地配置（本机证书 + 对端指纹）
     → 并行启动:
        - UDP 广播服务（每 5s 一次）
        - UDP 监听服务（端口 47100）
        - TCP 监听器（端口 47101）
     → 收到对端 UDP 包，校验指纹匹配
     → 仲裁谁主动（指纹字符串较小的一方主动 Connect）
     → 主动方发起 TLS 连接 / 被动方接受
     → TLS 握手时校验对端证书指纹 == 已存指纹
        匹配 → 进入 "已连接" 状态，UI 启用发送
        不匹配 → 拒绝连接，UI 提示 "对端身份变更"
```

### 断线

- TCP 连接断开（睡眠、关机、Wi-Fi 切换） → UI 状态 "离线"
- UDP 广播继续，再次发现对方就自动重连
- 文件传到一半断了：删除 .part 临时文件，气泡显示红色 "传输中断"，**不做断点续传**

## 协议帧与消息

### 帧格式（在 TLS 之上）

```
+--------+--------+------------------+
| 4 字节 | 1 字节 |  N 字节 payload  |
| len BE | type   |                  |
+--------+--------+------------------+
   总帧长 = 5 + len
```

每条消息一独立帧。`len` 不含自己。**最大 16MB**，超出关闭连接（防恶意大帧）。

### 消息类型

| Type | 名字 | payload 编码 | 用途 |
|------|------|------|------|
| 0x01 | HELLO | JSON | TLS 握手后第一条，交换 `{deviceName, protocolVersion}` |
| 0x10 | TEXT | JSON | `{"id": uuid, "text": "..."}` |
| 0x20 | FILE_OFFER | JSON | `{"id": uuid, "name": "x.png", "size": 12345, "mime": "image/png"}` |
| 0x21 | FILE_CHUNK | 二进制 | 16 字节 uuid + 后续原始字节（最多 256KB） |
| 0x22 | FILE_DONE | JSON | `{"id": uuid, "sha256": "..."}` |
| 0x23 | FILE_CANCEL | JSON | `{"id": uuid}`，单方面终止 |
| 0xF0 | PING | 空 | 30s 一次心跳 |
| 0xF1 | PONG | 空 | 心跳回应 |

### 文件传输流

```
发送方                         接收方
  |--- FILE_OFFER -------------->|  创建 %TEMP%\ft-{id}.part
  |                              |  UI 插入 "接收中" 气泡
  |--- FILE_CHUNK (256KB) ------>|  追加写入，更新进度
  |    ...                       |
  |--- FILE_DONE (sha256) ------>|  校验 sha256
  |                              |  匹配 → 移到接收目录
  |                              |  不匹配 → 删除并报错
```

**块大小 256KB**：兼顾吞吐和进度刷新粒度。

**自动接收**：对端是已配对的自己机器，文件直接接收，不弹"是否接收"。

**串行**：同时发多个文件 → 队列，前一个完才下一个。

**剪贴板图片**：Ctrl+V 粘贴图片 → 转 PNG → 作为文件名 `screenshot-yyyyMMdd-HHmmss.png` 走 FILE_OFFER。不额外开消息类型。

**接收目录**：默认 `%USERPROFILE%\Downloads\FileTransfer\`，重名加 `(1)` `(2)`。

### 设置（右上齿轮）

- 本机设备名
- 接收文件保存位置
- 开机自启（写注册表 `HKCU\...\Run`，默认关；本应用无托盘图标，开机自启会直接打开主窗口）
- "取消配对" → 删除本地配对信息，回到首次配对态
- 显示本机指纹（调试用）

**关窗行为**：点 × 关闭窗口 = 退出进程（无托盘常驻；用户未要求托盘）。会话内容随之清空。

### MVVM 绑定

```
MainViewModel
  ├─ ConnectionStatus  (Disconnected / Pairing / Online / Offline)
  ├─ PeerName          string
  ├─ Messages          ObservableCollection<MessageVm>
  │     ├─ TextMessageVm  { Text, IsOutgoing, Timestamp }
  │     ├─ FileMessageVm  { FileName, Size, Progress, State, IsOutgoing }
  │     └─ ImageMessageVm { Thumbnail, FullPath, IsOutgoing }
  ├─ InputText         string
  └─ Commands: SendTextCmd, PickFileCmd, CancelTransferCmd
```

Core 通过事件向 ViewModel 推消息；ViewModel 在 UI 线程 Dispatch 到 `Messages`。

## 错误处理

| 场景 | 处理 |
|------|------|
| 端口 47100/47101 被占用 | 顺延 +1 试到 +10，UDP 广播带上实际端口；都失败 → 启动错误对话框 |
| Windows 防火墙首次弹窗 | 文档说明 "首次启动请放行私有网络" |
| TLS 握手指纹不匹配 | 拒绝连接 + 提示 "对端身份变更，请取消配对后重新配对" |
| 传输中断（对方掉线） | 当前 FILE_OFFER 标失败，删 .part，气泡显红 "传输中断" |
| 磁盘写满 | 捕获 IOException，发 FILE_CANCEL，气泡显 "接收方磁盘已满" |
| 发送时文件被删/移动 | 读时 IOException，发 FILE_CANCEL，气泡显 "文件已不可访问" |
| 文件名含非法字符 | 接收端按 Windows 规则替换为 `_` |
| 同名文件 | 自动加 `(1)` `(2)` 后缀，不询问 |
| 双向同时建连 | 指纹小的一方主动，大的一方拒绝自连接 |
| 协议版本不匹配 | HELLO 中带 version，不匹配则断开，提示 "对方版本不兼容" |
| 心跳超时（30s 无 PING/PONG） | 主动关 TCP，状态 → "离线" |
| sha256 校验失败 | 删除接收到的文件，气泡 "文件损坏"，等用户重发 |

## 测试策略

### 单元测试（xUnit）

- 协议帧编解码：往返测任意 byte[]、超长帧拒绝、截断帧检测
- 配对码派生：相同输入恒定输出、跨字节序一致
- 指纹比较与"谁主动"仲裁
- 消息分发器：模拟 Stream 喂连续/拼接/分裂字节流，验证消息边界识别

### 集成测试

- 同进程内开两个 `Node` 实例（核心服务包装类），绑不同端口
- 走完整流程：UDP 发现 → 配对 → 文本互发 → 文件互发 → 断线重连 → 取消传输
- 用 `127.0.0.1` loopback，不依赖真实网络

### 手动验收

- 两台真机在同一 Wi-Fi 下：首次配对 → 互发文字 → 互发 5MB 图 → 互发 500MB 文件 → 拔网线
- 测开机自启写入注册表的正确性
- 测路由器 AP 隔离开启时是否给出友好提示

## 决策记录（why this not that）

| 选项 | 选了什么 | 为什么 |
|------|---------|--------|
| 网络范围 | LAN-only v1，跨网 v2 | YAGNI；跨网要部署 relay 或 NAT 穿透，工期×3 |
| 技术栈 | .NET WPF | 用户选 .NET；WPF 文档/AI 辅助/生态优于 WinUI 3 |
| 发现机制 | UDP 广播 | 自研协议简单；标准 mDNS（方案 B）扩展性优势在 2 台 Windows 场景用不上 |
| 传输协议 | 自定义二进制帧 over TLS | 只 8 个消息类型，自写解码 200 行；HTTP/WebSocket 在持久连接场景是过度设计 |
| 加密 | 自签 X.509 + TLS + 指纹固定 | 标准库现成；4 位配对码抗 MITM；不引入 PKI |
| 块大小 | 256 KB | 吞吐/进度粒度平衡点；1GB 文件约 4000 块进度条够顺 |
| 自动接收文件 | 是 | 对端是已配对的自己机器，弹确认是多余打扰 |
| 历史持久化 | 不做 | 用户明确选 "退出即清空" |
| 多文件 | 串行队列 | 避免带宽与磁盘争用，UI 更简单 |
| 断点续传 | 不做 v1 | YAGNI；用户场景下重传 500MB 也可接受 |
